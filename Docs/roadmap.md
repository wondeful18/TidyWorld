# TinyWorld · 课程路线图

课程目标、AI 协作入口和适用于所有章节的中文代码注释规范见项目总览。 [课程总览](../COURSE_OVERVIEW.md)

## 结业作品

从约 256 × 256 米的可玩样区起步，制作一张原创山谷与海岸地图。玩家从村庄出发，沿山坡道路穿过树林，经小桥或浅滩到达河口和海岸。地形高差安排视线和行进方向，道路、植被与水线都可以在编辑器里调整。结业地图以约 1 × 1 千米为初始制作上限，按内容与实测调整。

课程面向学过基本 C++ 语法的读者。坐标、采样和渲染知识随制作任务引入。每章交付可运行的演示，用固定机位截图、往返操作或数据记录验收。扩展实验可以独立选做。章节过长时按可独立验收的成果拆分。

Windows x64 / MSVC / D3D12 与 macOS arm64 / Metal 是首批验证目标。Linux x64 可在主线稳定后做移植实验。按平台记录构建、创建设备、呈现与交互实测。

### 阶段验收

- **第 08 章结束。** 交付一段带地表材质、能走能改的山谷样区，用相同机位记录雕刻前后。
- **第 15 章结束。** 交付从村口到海岸的可走路线，从步行视角检查道路、植被、过水点与观景点。
- **第 18 章结束。** 从门廊到海岸检查昼夜效果，同一机位验收太阳阴影与固定灯的烘焙结果。
- **第 21 章结束。** 复走同一条路线，交付场景文件、操作说明和可复现的性能记录。

## 项目结构与接口引入顺序

```text
TinyWorld/
  COURSE_OVERVIEW.md
  CMakeLists.txt
  CMakePresets.json
  vcpkg.json
  README.md
  cmake/                      # 平台、依赖和资源部署规则
  Engine/
    Core/                     # 日志与基础生命周期
    Platform/                 # GLFW、平台窗口句柄和 Surface 桥接
    Renderer/                 # WebGPU 上下文与渲染通道
  Editor/                     # 可执行程序、ImGui 和编辑工具
  Assets/Shaders/             # 与工程一同构建部署的 WGSL
  Chapters/ch01/              # 教程、截图和本章验证步骤
    src/                      # step1 至 step4，从空窗口到编辑器
  Docs/
    architecture.md
    roadmap.md
    Decisions/
```

上述为第一章目录。随章节加入 `Engine/Scene`、`Runtime/` 和共享资产目录。编辑器面板与 ImGui 后端归 `Editor`，场景、地形与渲染数据由 `Engine` 管理，步行与漫游逻辑归 `Runtime`。第 05 章在第 02 章场景容器上加入稳定对象 ID 与带版本的 JSON。第 17 章在 `Tools/` 加入离线 CPU 烘焙器。

- **第 2 章 · 约定空间。** 世界坐标右手系、Y 向上、单位为米，相机局部前向为 −Z。投影深度使用 WebGPU 的 0–1 范围。用一张图说明世界、裁剪、屏幕和纹理坐标，用简单几何验算投影、正面绕序和相机方向。讲清线性计算、sRGB 颜色纹理与线性数据纹理。glTF 导入时分别处理场景轴约定与资产自身朝向。 [WebGPU 规范](https://www.w3.org/TR/webgpu/) · [glTF 2.0 规范](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html)
- **第 06–12 章 · 共享世界数据。** 地形绘制、编辑器拾取、步行、道路和生态使用同一份高度数据与采样约定。场景保存稳定 ID、相对资产引用与源参数。道路网格和生态实例可以由源参数重建，生成实例与手摆对象各自管理。
- **第 04、08、13–15 章 · 共享环境与色彩约定。** 天空、车身和水面沿用一致的环境贴图朝向。水体在不透明绘制完成后读取其深度。选做后处理时，在线性场景颜色上完成处理，再做显示输出转换和编辑器界面合成。
- **第 17–18 章 · 静态灯与实时日照。** 光照贴图记录固定局部灯对静态表面的直接漫反射照明，太阳光和太阳阴影由实时通道计算。两部分在线性空间合成。
- **第 19–20 章 · 分开验收显示与加载。** 先在固定驻留场景里检查 LOD 接缝与裁剪，再用相同块键做加载与卸载。后台线程读取 CPU 数据，渲染线程按预算上传。漫游回归覆盖掉头、离开后返回与跨块。

第一章帧顺序为收集事件、开始 ImGui 帧、测量视口并准备纹理、提交 3D 通道、合成 UI、呈现。测量结果为零时暂停对应工作，避免零尺寸 Surface 或纹理。纹理作为后端约定的 `WGPUTextureView` 提交，视图需在本帧 UI 编码及提交过程中有效。固定版本将用户纹理的 bind group 按帧清理。对可恢复的 Surface 问题采用有限次恢复，Device Lost 单独记录并有序退出。所有回调状态在相关回调处理与资源释放期间保持有效。输入以 ImGui 的 capture 状态和视口焦点为依据。 [GLFW 窗口指南](https://www.glfw.org/docs/latest/window_guide.html) · [锁定版本的 ImGui WebGPU 后端头文件](https://github.com/ocornut/imgui/blob/b916186e66aa3c02b72c6ca17455516512ed8049/backends/imgui_impl_wgpu.h) · [锁定版本的后端实现](https://github.com/ocornut/imgui/blob/b916186e66aa3c02b72c6ca17455516512ed8049/backends/imgui_impl_wgpu.cpp)

## 课程交付与验收节奏

- **课内结构。** 每节从上一节的可运行结果起步，留下一项可观察的验收成果。保留第 01 章 Step 1–4 的分步入口。从第 07 章起维护同一条山谷路线，持续记录固定机位和步行视角。
- **章节历史。** `main` 保持最新可构建的教程工程。已验收的章节用 `chNN` annotated tag 记录终点。已发布标签保留，勘误用补丁标签或文档链接。章节目录保存教程、截图和轻量验证场景，共享资产和源代码引用项目统一目录。
- **验证层级。** 先验证全新构建，再验证带图形后端的启动，再验证场景与交互。CI 先承担具备条件的构建、纯 CPU 测试和场景数据检查。真实 GPU 跑通由对应环境记录。物理、PCG 和资源串流使用可复现输入，视觉章节至少提供固定相机的验收画面。
- **性能采样。** 第 11 章记录实例化基线，第 19–20 章沿用固定相机路线做对照，第 21 章汇总实测。记录分辨率、实例规模、图形后端、场景时刻和 Release 构建配置，比较帧时中位数与 P95、Draw Call、驻留块数和峰值上传。1080p/60 fps 的 16.7 ms 可用作测量参考。CPU 计时与后端支持的 GPU 时间戳分别记录。 [RenderDoc 平台与 API 支持](https://github.com/baldurk/renderdoc#api-support) · [Xcode Metal 抓帧](https://developer.apple.com/documentation/xcode/capturing-a-metal-workload-in-xcode)
- **内容制作。** 为第三方资产记录来源、授权与再分发条件。最终交付保存后的同一场景、可复现的漫游路线和性能记录。
